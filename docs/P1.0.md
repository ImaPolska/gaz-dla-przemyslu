## Założenia przyjęte bez pytania

- Wspólne źródło tokenów generuje semantyczne `theme.json` oraz paletę Blocksy. Header/Footer Builder pozostaje w Customizerze; po uruchomieniu test zgodności obu palet.
- Fonty lokalne WOFF2: A IBM Plex Sans; B Manrope + Source Sans 3; C Source Serif 4 + Source Sans 3. Zablokowany zdalny loader fontów Blocksy.
- Bez Companion. Free builder obsłuży układ; sticky/shrink zapewni CSS i skrypt motywu potomnego, nie natywna funkcja Companion.
- Identyczny WXR i treść dla A/B/C, wyłącznie bloki core i statyczne sloty; WordPress `latest`, PHP `8.3`.

## Otwarte pozycje

8 pozycji początkowych z sekcji 19, plus blokada publikacji po stronie środowiska agenta i potwierdzenie roboczego celu „24 h”. Szczegółowy rejestr wystąpień placeholderów zostanie wygenerowany z treści do `docs/open-items.md`; teraz nie ma pytań do zleceniodawcy.

## Ryzyka i co z nimi zrobiono

- `importWxr` w używanym kompilatorze instaluje `wordpress-importer`. Twardy zakaz wtyczek ma pierwszeństwo: WXR zostanie odczytany skryptem przez `runPHP`; odstępstwo zapisane w decyzjach.
- Nie ma możliwości zadeklarowania publicznych tagów ani testu publicznego linku bez publikacji. Lokalny test nie będzie przedstawiany jako test linku zdalnego.
- Blocksy jest motywem hybrydowym: ustawienia zapisujemy po aktywacji potomka, również do `theme_mods_gdp-child`; sama opcja rodzica nie wystarcza.
